# GT7 Companion — DI and routing

Evidence: [`docs/CODE_STYLE.md`](../../../docs/CODE_STYLE.md) sections E–F.

## Dependency injection

Everything is registered in one place: `lib/dependency_injection/app_scope.dart`, a `StatelessWidget`
whose `MultiProvider` wraps `MaterialApp.router` (`lib/app.dart`).

```dart
ChangeNotifierProvider(create: (context) => DgEdgeService()),
ChangeNotifierProxyProvider2<GT7InfoService, GTDBService, CarRepository>(
  create: (context) => CarRepository(
    Provider.of<GT7InfoService>(context, listen: false),
    Provider.of<GTDBService>(context, listen: false),
  ),
  update: (context, a, b, repository) => repository ?? CarRepository(a, b),
),
```

Rules:

- Register in dependency order and say why in a comment when the order is not obvious
  ("It follows the telemetry service, so it needs it first").
- Services and repositories: `ChangeNotifierProvider`.
- Repositories that depend on others: `ChangeNotifierProxyProvider`/`ProxyProvider2` with the idiom
  `update: (context, dep, instance) => instance ?? Repo(dep)`.
- Eager initialisation by cascade in `create`: `CarCatalog()..load()`.
- A bloc (if one is ever added here) is registered as
  `Provider<TBloc>(create: ..., dispose: (context, bloc) => bloc.close())` — not `BlocProvider`.
- Inside `create` use `Provider.of<T>(context, listen: false)`; in the UI use `context.read<T>()` and `Consumer<T>`.
- Close what you open: subscribe to a `ChangeNotifier` in the constructor, unsubscribe in `dispose()`.

Do **not** introduce: `BlocProvider`, `RepositoryProvider`, `context.select`, a service locator (`get_it`),
or page-level providers. None of these exist in the project.

## Routing

`lib/router/app_router.dart`:

```dart
@AutoRouterConfig(replaceInRouteName: 'Screen|Page')
class AppRouter extends RootStackRouter {
  @override RouteType get defaultRouteType => RouteType.adaptive();
  @override List<AutoRouteGuard> get guards => [];
  @override List<AutoRoute> get routes => [ ... ];
}
```

- Mark a screen with `@RoutePage()`; a class without a `Page` suffix generates `XDisplayRoute`.
- Structure: root `NestedWidgetRoute` (tab shell using `AutoTabsRouter.pageView`) → `HomeShellRoute`
  (plain `AutoRouter()`) → `HomePage` plus the vertical screens.
- Navigate with `context.router.push(const XRoute())`.
- `Navigator` only for a modal that returns a result:
  `await Navigator.of(context).push<bool>(MaterialPageRoute(builder: (_) => const LoginPage()))`,
  answered with `pop(true/false)`.
- No guards, deep links or redirect are configured; do not add them without a concrete need.
- A new screen is registered inside the right branch of `app_router.dart`, and if it belongs on the hub it
  also gets an `_AppTile` in `lib/pages/home_page.dart`.

After changing routes run `flutter analyze` — `app_router.gr.dart` is generated by `auto_route`.
