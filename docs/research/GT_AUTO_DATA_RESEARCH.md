# GT Auto: данные и предлагаемая функциональность

Проверено 25 октября 2026. Первый этап реализован по выбранному варианту «Мастерская»: официальный каталог (обновлён до 580 машин и фото), поиск/выбор автомобиля, GTPlus (характеристики и свапы), HRC Rolls (восемь специальных деталей), локальные планы с заметками. Данные сообщества загружаются при открытии один раз за сессию и по явному обновлению, с датой получения, источником и независимыми ошибками. Ниже — исходное исследование и дальнейшие возможности; сравнение двух машин, исходящие свапы, предельный тюнинг и аэродинамика остаются предложениями.

## Предлагаемый раздел

GT Auto стоит превратить в справочник возможностей конкретного автомобиля. Вверху — поиск/выбор машины, при наличии телеметрии — переход к текущей машине. Ниже четыре вкладки:

1. **Характеристики:** стоковые PP, мощность, момент, масса, привод, наддув, объём и габариты; сравнение двух машин. Для чисел показывать единицы и источник.
2. **Свапы:** двигатели, которые можно поставить в выбранную машину; отдельно — куда можно поставить её родной двигатель. Донор, код двигателя, цена источника, версия добавления. Для подтверждённых записей — сравнение стока со свапом.
3. **Потенциал и детали:** максимальная мощность с обычными/специальными деталями, минимальная масса, совместимость специальных деталей, диффузор и пределы прижимной силы.
4. **Мои сборки:** пользовательский список выбранных деталей и заметки, отдельно для стока и каждого свапа. Это следующий этап, не вычислитель физики игры.

Штатное обслуживание можно оставить отдельной справочной страницей. Не показывать кнопки «установить»/«купить», которые создавали бы впечатление управления самой GT7. В игре GT Auto и Tuning Shop — разные места; наш раздел может объединять справочные сведения о подготовке машины. [Официальное руководство](https://www.gran-turismo.com/gb/gt7/manual/gtauto/01).

## Что проверено технически

- Оба CSV экспортируются без авторизации:
  - `https://docs.google.com/spreadsheets/d/1XI_NeWovuYThKGf9nsqomwpUy_MCiheevohBmErvdHE/export?format=csv&gid=43176467`
  - `https://docs.google.com/spreadsheets/d/1XI_NeWovuYThKGf9nsqomwpUy_MCiheevohBmErvdHE/export?format=csv&gid=0`
- В ответе DG EDGE обнаружено 282 свапа, у GTPlus — 292. Это снимок на дату проверки, а не доказательство полноты одного источника. Расхождения надо сохранять и разбирать, а не заменять отсутствующую запись запретом свапа.
- В GTPlus есть `engineId`, `originId`, `carId`, `swapCarId`, `price`, `update`, `pp`, `power`, `torque`, `weight`, `displace`. Вложенная машина имеет числовой `code`; пример: Audi TTS Coupé '14 → 2169 → `car2169` нашего каталога. Часть объектов в Flight представлены ссылками, поэтому простое извлечение первого JSON-массива не является готовым парсером.
- Для 240 уникальных получателей с непосредственно вложенными объектами машин 237 кодов нашлись в локальном каталоге. Не найдены коды 3655, 3653 и 683 — их нельзя автоматически склеивать по похожему названию. Это предварительная проверка соответствия, не полная оценка всех записей.
- Локальный `assets/cars/cars.json` содержит 574 записи, текущий официальный сайт сообщает 580. Перед новым объединением нужно обновить каталог и проверить варианты/дубликаты. Сам генератор использует хешированный URL сборки сайта: сначала требуется проверить актуальный entrypoint.
- Используемый сейчас `https://gtdb.io/api/graphql_middleware/query/LegendCarsDealer` отвечает и отдаёт дилерские записи. Прямой `https://api.playstationdb.com/graphql` при проверке не прошёл TLS-проверку имени сертификата; проверку сертификата не отключал. Возможность получить через GTDB полный каталог деталей не подтверждена. Дилерские интеграции в этой задаче не менялись.
- [Страница свапов ddm999](https://ddm999.github.io/gt7info/engine-swaps) прямо помечена как больше не обновляемая, последняя указанная версия — 1.61. Сведения на страницах разработчика о частоте CSV не отменяют это предупреждение.

## Где пока есть пробелы

- **Wide body:** в двух проверенных вкладках нет отдельной полной матрицы доступности wide body. Условный код диффузора `1W` означает зависимость конкретного диффузора от широкого кузова, а не универсальный флаг wide body. Полный список расширений и цены для каждой машины не подтверждены.
- **Обычные детали:** подтверждённой полной базы «машина × каждая деталь × стоимость × эффект» не найдено. Восемь специальных улучшений можно показать уже на основе проверенной таблицы; остальные поля должны быть неизвестными до появления источника.
- **Состояние машины игрока:** текущая UDP-модель содержит carId и параметры движения/двигателя, но не список купленных и установленных деталей. Источник такого списка в исследовании не установлен. Сборки сначала вводятся пользователем.
- **Расчёт результата:** показатели после конкретного свапа в GTPlus можно показывать с его источником. Их нельзя использовать как универсальный калькулятор PP, мощности или управляемости для произвольной комбинации деталей. Максимальная мощность из таблицы — отдельный предельный сценарий, а не прибавка от одной детали.
- **Права и контракт:** доступность HTML/CSV не является лицензией на перепубликацию всей базы. Перед распространением снимков GTPlus/таблицы согласовать условия использования и атрибуцию с авторами; никому сообщений не отправлялось. [Условия GTPlus](https://gtplus.app/terms) не являются открытой лицензией на набор данных. У GT7Info проверен MIT-0, но он не распространяется автоматически на изображения и базы других сайтов.

## Как объединять

Внутренний ключ — официальный/телеметрический `carId`, представление `car2169`. Отдельная таблица соответствий хранит ID/slug каждого сайта и статус подтверждения. GTDB и DG EDGE используют собственные ID: нельзя считать любое число ID игровым.

Числа хранить с единицами: HP/BHP/PS не смешивать, lb переводить в kg, kgf·m в Nm только с явным коэффициентом. Нельзя подставлять `N/A`, пустую ячейку или отсутствие машины как нулевую мощность или «деталь недоступна». Для каждой группы данных сохранять источник, исходную версию игры, время получения и замечания о полноте. Не маркировать все PP версией текущего патча, если источник этого не гарантирует.

Архитектура: один сервис на внешний источник → нормализованные модели в `lib/models/gt_auto/` → `GtAutoRepository` объединяет по подтверждённым ID → Provider в AppScope → UI. Загрузки не размещать в виджетах. Для редко меняющихся таблиц — контролируемое обновление/кэш; не скачивать мегабайтные страницы заново при каждом открытии карточки.

Первую реализацию предлагаю ограничить поиском машины, стоковыми характеристиками, свапами и восемью специальными деталями, затем добавить предельные характеристики/аэродинамику и личные сборки. Wide body вынести в исследование до нахождения полноценного источника. Так каждый показанный показатель будет иметь проверяемое происхождение.

## Реализация первого этапа

- `GtPlusService`: объединяет транспортные Flight-фрагменты, разрешает ссылки целевых машин, сопоставляет только числовой код официального каталога. Свежий источник: 292 записи. Сравнение сток/свап использует значения одного GTPlus, а не смешивает их с официальным PP.
- `GtAutoPartsService`: UTF-8 CSV с кавычками/переносами строк, проверка заголовков, отдельные значения Yes/No/unknown. Сопоставление только по уникальному имени с нормализацией пробелов/регистра/апострофов.
- `GtAutoRepository`: частичные ошибки сохраняют данные другого источника; при неудачном обновлении прежние значения остаются с прежней датой и явной ошибкой. Планы независимы для каждой машины, запись в SharedPreferences упорядочена.
- Специальные детали показываются как совместимость базового автомобиля; влияние выбранного свапа на детали и их суммарные эффекты не вычисляются. Wide body и обычные детали остаются неизвестными.
- Производственных копий баз GTPlus/таблицы в assets не добавлено; тестовые фикстуры имеют атрибуцию и используются только для проверки парсера.
